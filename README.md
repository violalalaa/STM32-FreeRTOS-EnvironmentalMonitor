# 基于 STM32F103C8T6 与 FreeRTOS 的物联网温湿度监测系统


##  项目简介

本项目基于 **STM32F103C8T6** 微控制器与 **FreeRTOS** 实时操作系统，构建了一个多任务物联网温湿度监测系统。系统通过 **DHT11** 采集环境温湿度，在 **0.96 寸 OLED** 屏幕上实时显示，并利用 **ESP8266** 模块通过 **TCP** 协议将数据上传至云端/手机网络调试助手。项目采用队列与信号量实现任务间高效解耦，支持 **TCP 断线自动重连**，并提供了多样化的板载 LED 状态指示。

##  核心任务分解

- **Task_DHT**：每 1.5 秒采集一次温湿度数据，通过 `osMessageQueuePut` 将数据同时发送至 `Queue_OLEDHandle` 与 `Queue_WiFiHandle`，实现数据分发。
- **Task_OLED**：每 0.5 秒轮询信号量 `Sem_KeyHandle` 与队列 `Queue_OLEDHandle`，根据按键状态切换页面（温湿度页/提示页），并刷新显示。
- **Task_WiFi**：**（低优先级）** 阻塞等待 `Queue_WiFiHandle` 队列数据，通过 ESP8266 的 AT 指令封装并发送 TCP 数据包；若发送失败，自动执行 `AT+CIPCLOSE` → `AT+CIPSTART` 重连流程。
- **Task_Key**：采用 **下降沿检测 + 软件消抖**，检测到按键按下时释放信号量，触发 OLED 页面切换。
- **Task_LED**：根据全局错误计数器（`g_wifi_error_count`、`g_dht_error_count`）闪烁板载 LED，提供不同状态的可视化反馈。
---

##  功能

-  **多任务并发调度**：采集、显示、通信完全独立，互不阻塞，系统实时性强。
-  **队列/信号量解耦**：任务间通过 FreeRTOS 机制通信，降低耦合度。
-  **TCP 断线自动重连**：发送失败时自动清理旧连接并重新建立 TCP 会话，保证数据持续上云。
-  **状态指示灯**：
  - 正常运行：每秒心跳闪烁一次（亮 100ms，灭 900ms）；
  - WiFi 连续失败 ≥ 3 次：快速闪烁 5 次（周期 200ms）；
  - DHT 连续失败 ≥ 3 次：慢速闪烁 3 次（周期 600ms）；
-  **按键页面切换**：按一下按键，OLED 在“温湿度显示”与“自定义提示”页面间无缝切换。

##  调试过程中的踩坑与修复

**问题一：FreeRTOS 环境下 DHT11 一直读取失败**
- **排查**：忘记delay_init()与微秒级延时误用了 `HAL_Delay()`（依赖 SysTick），导致时序被打乱。
- **解决**：改用纯空转的微秒延时函数，并在读取时调用 `vTaskSuspendAll()` 挂起调度器保护关键时序，修复后数据稳定读取。

**问题二：ESP8266 数据发送卡死或丢失**
- **排查**：模块曾误入 AT 透传模式（`AT+CIPMODE=1`），导致后续 AT 指令被当作数据发送。
- **解决**：初始化时强制设置 `AT+CIPMODE=0`（非透传），并在每次发送前等待 ESP8266 返回 `>` 提示符。

**问题三：按键切换 OLED 屏幕出现乱码**
- **排查**：`sprintf` 格式化浮点数时，由于 **栈空间不足** 导致内存溢出。
- **解决**：将 OLED 任务的 `Stack Size` 从默认 128 字增大至 **512 字**。

调试策略：在排错过程中，我会先将所有任务替换为空壳，然后逐个解除注释并加入外设逻辑。这种模块化剥离的方式，能快速区分是系统调度问题还是外设驱动问题。


##  硬件接口说明
| 外设 | 引脚 | 备注 |
| :--- | :--- | :--- |
| DHT11 | PA1 | 需内部上拉 |
| ESP8266 | PA2(TX), PA3(RX) | USART2, 波特率 115200 |
| OLED 屏幕 | PB8(SCL), PB9(SDA) | 硬件 I2C |
| 板载 LED 心跳灯 | PC13 | 普通推挽输出 |
| 按键控制 | PA11 | 内部上拉，下降沿触发检测 |

  **电源警告**：ESP8266 模块必须由 3.3V 供电，**禁止直接接 5V**建议由 STM32 开发板的 3.3V 排针为 ESP8266 VCC 供电，以确保联网时大电流稳定。
